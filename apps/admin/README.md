# apps/admin — RowCat 운영 콘솔

실제 RowCat 배포를 운영하기 위한 조작 표면. `apps/web`(소비자 제품)과 **별개의 앱**이고,
공유하는 것은 계약·SDK·질의 정책·디자인 시스템뿐이다.

**이 앱이 운영 UI의 전부다.** 한동안 웹에도 `/moderation`이 있었고 같은 큐를 그렸는데, 그
화면은 지워졌다 — 운영 콘솔이 둘이면 신뢰성 개선(오프라인·낡은 값·멈춘 조회의 재시도)이
한쪽에만 들어가고, 둘 다 같은 API를 부르므로 그 어긋남은 아무 테스트도 깨뜨리지 않는다.
갈리는 축은 폴더 이름이 아니라 **누가 그 조작을 하는가**다:

```text
신고·이의 제출 · 내 제재 · 내 신고 · 알림   제품 기능   apps/web    ← 여기서 가져오지 않는다
큐 · 증거 검토 · 집행 · 이의 처리            운영 UI     apps/admin
모더레이션 도메인과 엔드포인트                공유        /v2/moderation/*
```

웹에서 들어오는 길은 계정 화면의 링크 하나이고(`canModerate`인 계정에만 보인다) 주소는 그
앱의 빌드 인자 `VITE_ADMIN_ORIGIN`이 정한다 — **미설정이면 그 링크가 그려지지 않는다.**
자세한 것은 `docs/moderation/ARCHITECTURE.md` §10에 있다.

```bash
pnpm --filter admin dev        # :3002
pnpm --filter admin build
pnpm --filter admin typecheck
pnpm --filter admin test
```

운영 권한이 있는 계정이 필요하다. 로컬에서는:

```bash
pnpm --filter @rowcat/api db:seed:dev-user
pnpm --filter @rowcat/api db:seed:moderator dev@rowcat.test admin
```

도커에서는 **기본 `docker compose up`에 함께 뜨고 3002를 호스트에 연다.** 한동안
프로필 뒤에 있었고 근거는 "내부 도구를 공개면에 두지 않는다"였는데, 이 앱의 접근 제어는
네트워크 위치가 아니라 서버의 인가다(아래 `requireModeratorViewer` 절) — 번들을 통째로
받아도 역할 없는 세션이 얻는 것은 403뿐이고, 정적 관리자 키가 없으므로 브라우저에 실려
새어 나갈 비밀도 없다. 반대로 프로필 쪽에는 조용한 실패가 있었다: 배포에서 콘솔이 통째로
빠진 것도 아무 증상이 없다.

```bash
docker compose up                   # web·api·db·redis + admin(:3002)
docker buildx bake admin            # 이미지 하나만 (기본·릴리스 그룹에도 들어 있다)
```

> **API의 `WEB_ORIGIN`에 이 앱의 오리진이 있어야 한다.** 빠뜨리면 콘솔의 모든 조회가
> CORS로 막히는데, 프리플라이트는 204로 통과하고 서버 로그에는 `[cors]` 경고만 남아
> 화면에서는 "네트워크 실패"로만 보인다. 로컬 기본값은 `http://localhost:3002`.

## 이 앱이 갖지 않는 것

목록이 이 문서의 절반이다. 없는 것이 결정이기 때문이다.

```text
대화 열람          기기의 것이다. 서버에 암호문만 있고 우리는 열쇠가 없다
동기화 복호화       운영자 권한은 제로지식 경계를 여는 근거가 되지 못한다
재생 페이로드 열람  저작 내용이다 — 신고된 작품의 원고만, 그 사건에 묶인 채로 보인다
정적 관리자 키      브라우저에 비밀을 싣지 않는다. 무엇보다 누가 했는지 알 수 없다
두 번째 집행 경로   숨김·정지·삭제는 전부 POST /v2/moderation/actions 하나를 지난다
감사 로그 편집·삭제 그 조작이 존재하지 않는다(서비스에 문장이 없고 라우트에 메서드가 없다)
자유 키 설정 폼     어휘 밖의 스위치 키는 서버가 거절한다(fail-closed)
```

## 구조

```text
src/app/router.tsx         라우트 트리 — **코드로 정의한다**(생성 파일이 없다)
src/components/            껍데기·표·확인 대화상자·상태 표면
src/features/<슬라이스>/    화면. 순수 판정은 옆의 .ts로 뺀다
src/lib/                   API 클라이언트·인증·운영자 판정·표시 포맷
```

### SSR이 없다

`apps/web`이 TanStack Start로 서버 렌더를 하는 것과 갈리는 유일한 큰 차이이고, 이유가 둘이다.

1. **특권 데이터를 HTML로 굳히지 않는다.** SSR이면 회원의 이메일과 제재 이력, 비공개 작품의
   제목이 서버가 그린 문서에 실려 나가고 그 문서는 프록시·브라우저 캐시·뒤로가기 스냅샷에
   남는다. 이 앱이 답해야 하는 질문 중에 첫 페인트의 속도로 이득을 보는 것은 하나도 없다.
2. **인가 판정이 한 곳이 된다.** 순수 SPA에서는 모든 데이터가 같은 API 호출을 지나고, 그
   호출은 전부 서버 게이트를 만난다.

### 인가

```text
requireModeratorViewer   staff·admin   운영 조회 전부
requireAdminViewer       admin만       성인 자격 · 관리형 생성 허용 · 작품 삭제 · 기능 스위치 · 최소 앱 버전 · 앱 업데이트 공지 발송
```

**둘 다 `requireActiveViewer` 위에 선다** — 정지·차단된 운영자는 역할 컬럼이 남아 있어도
들어오지 못한다. 계정을 빼앗긴 관리자가 그 계정으로 남의 계정을 여는 경로가 없어야 한다.

화면의 게이트(`lib/operator.ts`)는 **인가가 아니라 깜빡임 방지**다. 실제 거절은 모든 조회가
서버에서 받는 403이고, 그 파일을 지워도 목록은 비어 있다.

### 모션

웹과 **같은 체계**를 쓰고 값은 `@rowcat/design` 하나에서 온다. 움직이는 것은 둘뿐이다 —
화면이 들어올 때의 등장(`PageEnter`)과 사이드바의 활성 표시(`MotionActiveIndicator`).

표의 줄에는 등장도 재배치도 없다. `더 보기`로 이어 붙은 스무 줄이 하나씩 떠오르면 목록이
방금 만들어진 것처럼 읽히고, 운영 표는 훑는 표면이라 그 대가가 특히 크다.

`lib/motion/transitions.ts`가 `apps/web`의 사본인 것은 의도한 것이다 — 두 앱이 서로를
import하지 않는 경계가 먼저이고, 리듬의 출처는 `@rowcat/design` 하나라 사본에 있는 것은
단위 변환뿐이다.

### 파괴적 조작

전부 `components/confirm-dialog.tsx` 하나를 지난다. `window.confirm()`을 쓰지 않는 이유는
그것이 사유를 받을 수 없고, 대상을 보여 줄 수 없고, 실패를 표시할 자리가 없고, 무엇보다
결과를 기다리는 동안 화면이 얼어붙기 때문이다.

대화상자가 요구하는 것: **무엇을 · 어디에 · 무슨 결과 · 왜**. `consequence`가 선택이 아닌
이유는 "정말 삭제하시겠습니까?"가 아무 정보도 주지 않아 읽지 않고 누르는 문장이 되기
때문이다.

### 관리형 생성 허용은 비용의 경계다

결제가 없는 공개본에서 관리형 생성은 **운영자의 제공자 키**로 돈다. 지출을 묶는 것은 둘이다 —
서버의 속도 제한(분당·하루)이 한 사람이 쓰는 양을, 회원 상세의 `관리형 생성 허용` 스위치가
**쓰는 사람**을 묶는다(`POST /v2/admin/members/:id/managed-generation`, admin 전용, 감사
`admin.member.managed_generation.set`).

```text
MANAGED_GENERATION_ACCESS=allowlist   기본값. 목록에 오른 회원과 staff·admin 역할만 쓴다
MANAGED_GENERATION_ACCESS=everyone    목록이 쓰이지 않는다 — 모든 회원이 쓴다
```

이 값을 내리는 것은 제재가 아니다. 막힌 회원은 자기 API 키(BYO)로 가는 길을 안내받고, 그래서
조치 원장이 아니라 감사 로그에 남는다(성인 자격 스위치와 같은 판단이다). 화면은 배포 모드를
모르므로 두 예외(역할·`everyone`)를 결과로 단정하지 않고 확인 문장 안에서 함께 말한다.

### ⚠️ 최소 앱 버전이 가장 위험하다

스토어에 없는 버전을 하한으로 세우면 **모든 모바일 사용자가 앱에서 잠기고**, 그 상태는
스토어 심사가 끝날 때까지 되돌릴 수 없다(앱을 이미 잠갔으므로 앱으로는 아무것도 알릴 수
없다). 서버는 그 값이 스토어에 있는지 알 방법이 없어 막지 못한다 — 막는 것은 화면의 명시적
확인이고, 남는 것은 감사 기록이다.
