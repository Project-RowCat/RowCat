# 소스 없이 설치하기 — `scripts/install.sh`

**저장소를 내려받지 않은 서버에서, 게시된 이미지로 운영 배포를 세우고 올린다.** 필요한 것은 Docker(Compose 2.24
이상)와 `curl`뿐이다 — Node, pnpm, 빌드가 없다. 개발 환경은 `pnpm dev:setup`이고, 저장소 체크아웃에서 직접
`docker compose up`하는 길(`docs/oss/SELF-HOSTING.md`)도 그대로 남는다. 이 문서는 그 둘이 아닌 **운영자의 길**이다.

```bash
curl -fsSLO https://raw.githubusercontent.com/Project-RowCat/RowCat/<릴리스>/scripts/install.sh
less install.sh                                   # 실행할 것을 먼저 읽는다
bash install.sh --ref <릴리스> --domain rowcat.example.com --email ops@example.com
```

`<릴리스>`는 날짜로 된 소스 릴리스(`docs/oss/RELEASE.md`)나 커밋이다. `curl … | bash`로 바로 넘기지 않는 것은
읽을 기회를 남기기 위해서다 — 이 스크립트는 비밀을 만들고 서버에 포트를 연다.

## 하는 일

```text
설치    그 커밋의 이미지 셋을 당겨 다이제스트를 적는다       당겨지지 않으면 여기서 멈춘다 — 아무것도 쓰지 않았다
        그 커밋의 docker-compose.yml · deploy/caddy/ · scripts/{backup,restore,install}.sh
        .env — 세션 키와 DB 비밀번호를 생성해 0600으로       이미 있으면 덮지 않는다(그것은 업그레이드다)
        compose.images.yml — 이미지를 다이제스트로 고정, build 제거
        docker compose up --wait → 첫 실행 설정 코드를 보여 준다
업그레이드  같은 디렉터리에서 --ref만 바꿔 다시 실행
        새 이미지를 먼저 당긴다 → scripts/backup.sh → 파일 교체 → .env의 태그만 바꾼다 → 고정 → up --wait
```

- **`--domain`이면 HTTPS다.** `deploy/caddy/`가 웹·API·콘솔을 `<도메인>`·`api.<도메인>`·`admin.<도메인>`으로
  세우고 인증서를 스스로 받는다(`docs/ops/HTTPS.md`). 세 이름이 이 서버를 가리키고 80·443이 열려 있어야 한다 —
  스크립트는 DNS를 확인하지 않는다. 그 전에 띄워도 스택은 서고, 인증서만 이름이 닿을 때 나온다.
- **`--local`은 이 컴퓨터에서 써 보는 것이다.** 3000–3002를 평문 HTTP로 연다. 서버에서 쓰면 그 포트가 방화벽이
  허락하는 어디에서든 TLS 없이 닿는다.
- **둘 중 하나를 반드시 고른다.** 기본값을 두면 서버 운영자가 모르는 사이 평문 배포를 세운다.
- **포크는 `--repo 소유자/이름`.** 파일과 이미지가 함께 따라간다(`ghcr.io/<소유자 소문자>/rowcat`). 다른 곳에
  게시했으면 `--registry`. 둘 다 처음 설치할 때 한 번만 준다 — `.env`에 적히고(`ROWCAT_INSTALL_REPO`,
  `ROWCAT_IMAGE_REGISTRY`) 업그레이드는 그 값을 쓴다. 기본값으로 다시 계산하면 포크 배포가 같은 날짜 태그를 가진
  이 저장소의 코드와 이미지로 아무 오류 없이 옮겨 간다. 다른 `--repo`를 주면 업그레이드가 거절한다.

## 하지 않는 일과 그 이유

- **빌드하지 않는다.** 고정 파일이 compose의 `build:`를 지운다. 이미지가 없으면 그 이미지를 이름으로 대며 실패한다 —
  저장소의 `docker-compose.yml`은 당기기가 거절되면 조용히 체크아웃을 빌드하는데(`CLEAN-INSTALL.md`), 소스가 없는
  서버에서 그 길은 알아보기 힘든 `lstat apps` 오류로 끝난다.
- **`latest`를 돌리지 않는다.** 배포는 한 커밋의 이미지를 **다이제스트로** 돌린다. `sha-<커밋>` 태그도 이미지
  워크플로를 다시 돌리면 같은 이름으로 다른 바이트가 올라갈 수 있다 — 다이제스트는 바이트의 이름이라 재시작이
  다른 것을 띄울 수 없다. 옮기는 것은 이 스크립트를 다시 실행하는 것뿐이다.
- **`.env`를 덮지 않는다.** `BETTER_AUTH_SECRET`은 세션을 서명하고 2단계 인증 비밀도 암호화한다. 새로 만들면
  모두 로그아웃되고 인증 앱이 영영 꺼진다. 업그레이드는 태그 줄만 바꾼다.
- **남은 DB 볼륨 위에 설치하지 않는다.** 컴포즈 프로젝트 이름이 `rowcat`으로 고정이라 볼륨은 기계 전체에서 하나다.
  남은 볼륨은 예전 비밀번호를 가지고 있어 새로 만든 것을 거절한다 — 스크립트는 시작 전에 그것을 말하고 멈춘다.

## 다이제스트 고정의 한계

고정되는 것은 **설치할 때 레지스트리가 내준 것**이다. 이미지에 서명(cosign 등)은 없고, 스크립트가 다이제스트를
비교할 공개 기록도 없다 — 처음 당긴 순간의 신뢰는 레지스트리와 저장소 소유자의 계정에 달려 있다. 고정이 막는
것은 그 뒤의 일이다: 이후의 푸시, 태그의 재사용, 레지스트리 쪽 교체가 이미 선 배포를 바꾸지 못한다.

이미지는 `linux/amd64`·`linux/arm64` 두 가지다. 다이제스트는 그 둘을 묶은 인덱스의 것이라 두 서버가 같은 값을
적는다.

**GHCR 패키지가 공개여야 한다.** 비공개이면 익명 당기기가 거절되고 스크립트는 그 첫 단계에서 멈춘다. 공개로 바꾸는
것은 패키지 소유자의 설정 하나다(`CLEAN-INSTALL.md`에 확인 명령이 있다).

## 업그레이드와 롤백

```bash
bash scripts/install.sh --ref <새 릴리스>          # 배포 디렉터리에서
```

DB가 떠 있어야 백업이 된다. 백업 없이 올리려면 `--skip-backup`을 **알고** 준다. 되돌리기는 `docs/ops/BACKUP.md`
§롤백이다 — 새 이미지가 마이그레이션을 적용한 뒤에는 옛 이미지로 그 DB를 띄울 수 없고, 직전 덤프를 빈 볼륨에
복원한 뒤 이전 `--ref`로 다시 실행하는 것이 길이다.

## 검증

`pnpm test:install`(`scripts/install-smoke.sh`)이 127.0.0.1의 임시 레지스트리를 GHCR 대신 세우고, 소스 없는
디렉터리에 설치한다: 거절(없는 태그, 형태 미지정, 같은 디렉터리의 두 번째 설치), `.env` 0600과 생성된 비밀,
다이제스트 고정, 다섯 서비스와 세 표면, 설정 코드, API 재시작과 `down`/`up`, 그리고 라벨 하나만 다른 이미지로의
업그레이드(먼저 백업, 비밀 유지, 고정 이동, 실행 중인 이미지가 고정한 것). 로컬 데몬에 이미지 셋이 있어야 한다 —
CI의 `compose` 잡이 `compose-smoke.sh --build` 뒤에 돌린다.

증명하지 못하는 것: **실제 GHCR에서의 당기기**(패키지 공개 뒤 한 번 손으로 본다), 공개 도메인의 인증서 발급
(`HTTPS.md`), 서로 다른 커밋 사이의 마이그레이션(`scripts/upgrade-smoke.sh`).
