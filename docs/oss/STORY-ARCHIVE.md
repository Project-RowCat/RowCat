# 작품 파일 — 한 인스턴스의 초안을 다른 인스턴스로

**사람이 들고 가는 파일 하나다.** 연합(federation)도, 인스턴스 사이 API도 없다. 만든 사람이 자기 초안을
`.rowcat.zip` 하나로 내보내고, 다른 RowCat 배포의 `/create`에서 그 파일을 **새 초안**으로 가져온다.

```text
편집기 머리 `파일로 내보내기`   초안 + 자식 기록 + 이미지·소리 바이트 → 매니페스트 + media/<sha256>.<ext>
/create 머리 `파일 가져오기`    압축 풀기 → 검사 → 업로드(그 서버가 새 id를 준다) → 새 초안 한 건
```

규칙은 `packages/authoring/src/story-archive.ts`(순수 — 모양·한도·매핑), 앱 쪽은
`apps/web/src/features/create/archive/`(zip·해시·업로드·쓰기)에 있다.

## 1. 단위가 초안인 이유

- **런타임 원본은 초안에만 있다.** 서버는 발행 때 원본을 컴파일하고 버린다(`### Runtime publication and
  playback`). 발행본을 옮기면 런타임 작품은 코드 없이 도착한다.
- **"누구의 작품인가"의 답이 구조로 선다.** 이 기기의 초안만 내보낼 수 있다 — 남의 발행 작품을 파일로 꺼내는
  길은 없다. 가져오기 화면은 "직접 만든 작품이거나 옮길 권리가 있는 것만"이라고 적는다. 그 문장 말고 서버가
  검증하는 것은 없고, 그렇다고 주장하지도 않는다.

## 2. 파일에 없는 것

| 없는 것 | 이유 |
| --- | --- |
| 회원 id · 닉네임 · 이메일 · 세션 · 동기화 키 | 파일은 작품을 옮긴다. 계정이 아니다 |
| `publishedStoryId` · `rev` · `fieldRev` · `dirty` · 묘비 | 이 기기 사본의 사실이다. 다른 인스턴스에서는 아무것도 가리키지 않는다 — 가져온 초안은 미발행이다 |
| 미디어 id | 내보낸 서버의 행 이름이다. 바이트가 대신 가고, 가져오는 기기가 자기 서버에 올려 새 id를 받는다 |
| 대화 · 메모리 · 페르소나 · 플레이 저장 | 작품이 아니라 읽은 사람의 것이다 |

출처는 `source.origin`(내보낸 웹의 오리진) **하나**만 남는다. 정보용이며 가져오기는 그 값을 읽지 않는다.

## 3. 형식 (버전 1)

zip 안에 매니페스트 하나와 미디어 파일들이 있다. 그 밖의 항목이 있으면 **풀기 전에** 거절한다.

```text
rowcat-story.json            매니페스트 (deflate)
media/<sha256>.<ext>         이미지·소리 바이트 (저장만 — 이미 압축된 형식이다)
```

```json
{
  "format": "rowcat-story",
  "version": 1,
  "exportedAt": "2026-11-03T05:00:00.000Z",
  "source": { "origin": "https://rowcat.example" },
  "story": {
    "title": "밤의 도서관", "tagline": "", "description": "", "tags": ["미스터리"],
    "orientation": "all", "adult": false, "visibility": "private", "promptProtected": false,
    "prompt": "…", "defaultStartScene": 0
  },
  "cover": "media/3f…a1.webp",
  "lore": [{ "keys": ["사서"], "content": "…", "constant": false, "position": "system_bottom", "order": 0 }],
  "startScenes": [{ "title": "첫 밤", "content": "…" }],
  "sceneImages": [{ "trigger": "night", "image": "media/9c…04.webp" }],
  "runtime": {
    "enabled": true, "entry": "src/main.tsx",
    "files": [{ "path": "src/main.tsx", "content": "…" }],
    "assets": [{ "kind": "image", "path": "characters/sena/smile", "media": "media/9c…04.webp" }]
  },
  "media": [{ "path": "media/9c…04.webp", "mime": "image/webp", "bytes": 48213, "sha256": "9c…04" }]
}
```

- **경로가 곧 내용의 sha256이다.** 같은 그림을 두 곳에서 쓰면 파일은 하나다. 가져오기는 모든 바이트의 해시와
  크기를 다시 재고, 하나라도 다르면 아무것도 올리지 않는다(`media_mismatch`).
- **id 대신 위치.** 기본 시작 장면은 `startScenes`의 **인덱스**, 미디어 참조는 경로다. 목록은 화면과 같은
  순서로 정렬해 쓴다.
- **참조는 닫힌 집합이다.** 매니페스트가 가리키는 미디어는 모두 `media`에 있어야 하고, `media`의 항목은
  모두 어딘가에서 쓰여야 하며, 형식은 그 자리(표지·상황 이미지·런타임 이미지·런타임 소리)가 받는 것이어야
  한다. 런타임 파일 경로는 저작 규칙(`checkRuntimePath`)을, 런타임 자산 이름은 스튜디오·발행과 **같은
  함수**(`classifyRuntimeAssetValue`, 논리 이름만)를 통과해야 한다 — 원격 주소는 자산 이름이 될 수 없다.
- **`visibility: "archived"`는 `private`로 들어온다.** 보관은 발행본의 상태 전이이지 초안이 고르는 공개
  범위가 아니다.
- **버전이 더 높은 파일은 거절하고 그렇게 말한다**(`newer_version` — 파일이 깨졌다가 아니라
  "더 새 RowCat에서 만든 파일이니 이 RowCat을 업데이트하라"). 읽을 수 없는 모양을 반쯤 읽지 않는다. 형식을 넓히는 변경은 버전을 올리고,
  이 모듈이 낮은 버전을 접어 읽는다.

## 4. 한도

| 항목 | 값 |
| --- | --- |
| 파일 전체 | 매니페스트 32 MiB + 미디어 합 256 MiB |
| 미디어 한 개 | 그 자리의 업로드 한도 그대로(표지·상황 이미지·런타임 이미지·런타임 소리) |
| 항목 수 | 표지 1 + 상황 이미지 200 + 런타임 자산 한도 |
| 글 · 목록 길이 | `STORY_ARCHIVE_LIMITS` — 진행 중인 초안이 담을 수 있는 만큼. 발행은 발행 한도로 다시 검사한다 |

크기는 zip 항목이 **선언한 원래 크기**로 풀기 전에 재고, 넘으면 풀지 않는다(압축 폭탄). 선언과 실제가 다르면
해시 검사가 잡는다.

## 5. 가져오기의 순서

1. 풀기 · 매니페스트 검사 · 해시 검사 — 실패하면 아무것도 바뀌지 않았다.
2. **업로드** — 스튜디오가 쓰는 세 문(`/me/scene-images` · `/me/runtime-assets` · `/me/runtime-audio`)
   그대로. 서버는 바이트를 다시 디코드하고 정규화한다 — 파일을 거쳤다는 것은 아무것도 건너뛸 근거가 아니다.
   업로드 한도(`mediaUpload`)에 걸리면 **남은 시간을 보여 주고 기다린다**. 더 일찍 다시 보내면 또 거절된다.
3. 계정 확인 — 그 사이 다른 계정으로 바뀌었으면 쓰지 않는다.
4. **쓰기** — 새 초안 → 로어 → 시작 장면 → 상황 이미지 → 런타임(파일이 있을 때만) → 표지. 도중에 실패하면
   만들던 초안을 지운다. 반쯤 된 초안은 남기지 않는다.

**표지는 올리지 않는다.** 표지는 발행 때까지 이 기기가 쥐고 있는 바이트다(`draftCovers`) — 내보낸 쪽과
똑같이 가져온 쪽도 기기에 둔다.

**대화상자를 닫으면 취소다.** 쓰기는 업로드가 모두 끝난 뒤에야 시작하므로, 취소된 가져오기는 초안을 남기지
않는다. 이미 올라간 미디어는 남는다 — 아무것도 가리키지 않는 런타임·상황 이미지는 서버가 "아무도 가리키지
않는다"고 말할 수 없는 종류다(`### Background jobs` 고아 정리). 알려진 비용이다.

## 6. 하지 않는 것

- **중복 감지.** 파일에는 이 기기가 맞춰 볼 신원이 없고, 제목으로 추측하면 두 작품이 하나로 합쳐진다.
  같은 파일을 두 번 가져오면 초안이 두 건 생긴다.
- **덮어쓰기 · 병합.** 가져오기는 언제나 새 초안이다.
- **보호 원고의 보호.** `promptProtected`는 이 제품 화면의 표시 정책이다. 파일은 원고 전체가 **평문**이고,
  내보내기 대화상자가 파일이 생기기 전에 그렇게 말한다. 암호화·비밀번호는 없다.
- **발행 · 공개 상태 이전.** 가져온 초안은 미발행이고, 발행은 새 인스턴스의 발행 절차(성인 자격 포함)를 처음부터
  거친다.
- **모바일.** 앱에는 아직 내보내기·가져오기가 없다. 규칙이 `@rowcat/authoring`에 있는 이유가 그 자리다 —
  앱이 가져오기를 만들 때 같은 함수를 부른다.
- **다른 제품의 형식.** 캐릭터 카드(PNG/JSON) 같은 바깥 형식을 읽는 것은 이 형식의 일이 아니다. 필요해지면
  그 형식을 이 매니페스트로 접는 **별도의 변환기**로 세우고, 이 스키마에 바깥 필드를 들이지 않는다.
