# 공개본 비밀·노출 감사

> 기록 문서다. 공개 저장소와 그것이 내보내는 것에 비밀이나 공개하지 않을 정보가 남았는지 한 번 독립적으로
> 확인했고, 무엇을 어떻게 봤는지와 결과를 적는다. 다시 할 때는 §다시 하기를 따른다.
> 찾은 것의 **값은 적지 않는다** — 이 문서도 공개된다.

## 범위

2026-10-31, 공개 원격(`Project-RowCat/RowCat`)이 가진 ref 전부를 대상으로 했다 — `main`(a780871)과 태그
`desktop-2026-10-31`(같은 커밋). 그 밖에 저장소가 내보내는 표면도 봤다.

| 표면 | 본 것 |
| --- | --- |
| git 현재 트리 | 추적되는 파일 전부 |
| git 히스토리 | 공개 루트(1bdf364) 이후 23커밋의 모든 blob(3,289개), 지워진 줄, 커밋 메시지·작성자 |
| 컨테이너 이미지 | `apps/*/Dockerfile`과 `.dockerignore` — 무엇이 이미지 층에 들어갈 수 있는가 |
| 데스크톱 설치 파일 | `apps/desktop`의 묶음 허용 목록(`scripts/build-app.ts`), 릴리스 `desktop-2026-10-31` |
| npm `@rowcat/mcp` | 이 저장소의 `files`, 레지스트리에 이미 올라간 판의 메타데이터(내려받지 않았다) |

## 방법

세 가지를 서로 모르게 돌렸다.

1. **기계 스캔** — 모든 blob의 모든 판에 자격 증명 규칙(클라우드·VCS·결제·AI 제공자 키, PEM 개인 키, JWT,
   비밀번호를 품은 연결 문자열, 고엔트로피 문자열)과 노출 규칙(이메일, 전화번호, 사업자·통신판매·주민등록번호
   모양, 공인 IP, 호스트, 내부 도구 링크, 운영자 도메인, 클라우드 계정 ID)을 걸었다. 이미지 파일은 EXIF·GPS·XMP를 봤다.
2. **gitleaks 8.21.2** — 히스토리(각 커밋이 더한 줄)와 작업 트리.
3. **독립 검토** — 표면을 열로 나눠 각각 다른 검토자가 읽었고(서버, 웹 둘, 모바일·데스크톱, 패키지, 문서·CI,
   히스토리, 배포물, 스캔 결과 분류), 나온 후보마다 **반박하라고** 지시받은 검증자가 따로 확인했다. 마지막에
   누구도 맡지 않은 표면을 찾는 검토자가 한 번 더 돌았다.

## 결과

**공개 표면에 실제 자격 증명은 없다.** 키 모양을 한 값은 전부 테스트가 일부러 심은 가짜(`SUPER-SECRET-TEST-VALUE`,
`example.internal`의 합성 비밀번호, 실행 중에 만드는 키의 PEM 틀, 동기화 골든 벡터)다. 작성자 신원은 GitHub
noreply 주소 하나, 개인 정보 모양의 값은 전부 지어낸 것(`010-0000-0000`, `example.test`의 이름)이다. 사업자 정보·약관
본문·팩 본문·운영 값은 PLAN.md의 「히스토리」 결정대로 어느 커밋에도 없다.

### 저장소 밖에서 할 일 — 운영자의 결정

- **npm에 이미 올라간 `@rowcat/mcp` 판**(공개 전)의 메타데이터가 옛 운영자의 홈페이지와 지원 주소, 옛 라이선스를
  가리킨다. 그 판은 종료된 API를 가리킨다고 이미 적혀 있다(PLAN.md D6). 고치려면 공개 트리에서 새 판을 태그
  워크플로로 내고(FORKING.md §13) 옛 판을 `npm deprecate`한다 — 배포 권한이 있는 사람의 일이다.
- **GitHub의 비공개 취약점 신고**가 공개 저장소에서 켜져 있는지 확인한다(SECURITY.md가 그 경로를 약속한다).
- `apps/desktop/README.md`가 적었듯 허용 목록 전의 **로컬 빌드 설치 파일**은 개발자의 `apps/api/.env`를 실었다.
  그런 파일이 이 컴퓨터 밖으로 나간 적이 없는지 확인하고, 모르면 그 `.env`에 있던 값을 바꾼다. 공개 릴리스
  `desktop-2026-10-31`은 `.env`가 없는 CI에서 허용 목록으로 묶였다.
- **공개 원격에는 `main`과 태그만 민다.** 공개 전 작업을 했던 클론에는 공개하지 않을 ref와 객체가 남을 수 있다 —
  `git push --all`·`--mirror`를 쓰지 않는다.

## 다시 하기

- 히스토리 스캔은 CI가 커밋마다 한다(`.github/workflows/ci.yml`의 `secrets` — gitleaks, 이미지는 digest 고정,
  네트워크 없음, 읽기 전용). 이 잡도 릴리스 관문이다(`scripts/ci-passed.sh`). 허용 목록은 `.gitleaksignore`이고
  한 줄마다 사람이 본 근거를 단다.
- gitleaks가 보지 않는 것 — 개인 정보, 운영자 식별자, 내부 메모, 제3자 저작물 — 은 규칙으로 닫히지 않는다.
  공개 전에 한 번 더 사람이(또는 독립 검토자가) 위 표면을 읽는다. 운영자 도메인만은 `operator-domain.test.ts`가
  현재 트리에서 막는다.
