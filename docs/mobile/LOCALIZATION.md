# 모바일 — 영어·한국어로 그리는 한 앱

> 결정 기록이자 번역 기여 안내. DEV-18. 웹은 이미 두 언어로 그려진다(`apps/web/src/lib/i18n/`); 이
> 문서는 앱이 같은 두 언어로 그려지는 모양과, 화면을 하나씩 옮기는 절차를 정한다.

## 지금의 모양

```text
사전          apps/mobile/src/lib/i18n/messages/{en,ko}/<이름 공간>.ts   영어가 원본, 한국어는 같은 모양
인스턴스      lib/i18n/instance.ts     i18next 하나 · 두 사전을 다 싣고 동기로 초기화
판정          lib/i18n/locale.ts       선호 + 기기 언어 → 그릴 언어 (순수)
선호          lib/i18n/preference.ts   기기 키-값(rowcat_device.db, rowcat.locale.preference)
기기 언어     lib/i18n/device-locale.ts  Hermes `Intl`의 기본 로캘 — 네이티브 모듈 없음
뿌리          lib/i18n/provider.tsx    첫 프레임 전에 적용 · 시스템을 따르는 동안 앞으로 올 때 다시 읽음
고르는 자리   설정 › 일반 › 화면 › 언어 (회원) · 머리말의 언어 단추 (게스트)
```

옮겨진 화면: **껍데기**(발견 머리말·서랍·바닥 줄) · **로그인**(로그인 화면·2단계 인증·실패 문장) ·
**설정**(껍데기·분류 줄·일반의 화면·이 기기의 데이터) · **발견**(검색·필터·정렬·카드·빈 상태) ·
**작품 상세**(시작·즐겨찾기·공유·정보·관련 작품·댓글과 답글) · **신고와 이의 제기**(신고 창·내 신고·이용 제한·
이의 제기 창) · **페르소나**(설정의 라이브러리·폼, 대화 설정과 시작 창이 읽는 문구) · **공개 프로필**(머리·
팔로우·차단·작품 목록). 그 밖의 화면은 아직 영어 문자열을 코드에 들고 있다 — 아래 §남은 것.

## 결정

- **언어는 기기의 값이다 — 회원의 값이 아니다.** 밝기와 같은 축이고 같은 파일에 산다. 로그인 화면·대기
  화면·게스트에게도 언어가 있어야 하고, Alice가 로그아웃하고 Bob이 들어와도 언어가 바뀌지 않아야 한다.
  회원 SQLite에는 그 자리가 없고, 계정에 두면 로그인 전 화면이 언어를 모른다. 웹이 쿠키(브라우저의 값)에
  두는 것과 같은 판단이다. **기기 데이터 초기화가 지우지 않는다**(그 조작은 회원 데이터베이스 하나를 지운다).
- **기본은 `system`이다.** 고르지 않은 사람은 휴대폰의 언어로 본다. 휴대폰이 두 언어 어느 것도 아니면
  영어다(원본 언어). 저장된 값이 깨졌거나 모르는 값이면 `system`으로 읽는다 — 첫 프레임이 읽는 값이라 던지면
  앱이 뜨지 않는다.
- **네이티브 모듈을 더하지 않았다.** `expo-localization`은 OS의 선호 언어 목록 **전체**를 주지만 네이티브
  모듈이라 지문이 바뀌고 새 런타임 세대와 새 바이너리가 필요하다. Hermes의 `Intl`이 기본 로캘을 플랫폼에서
  가져오므로(Apple은 선호 언어의 첫째, Android는 기본 `Locale`) 첫째 언어는 의존 없이 얻는다. 값: 이 변경은
  **OTA로 나간다**(`pnpm mobile:runtime:check`가 기록과 같다). 비용: "프랑스어, 그다음 한국어"로 둔 휴대폰은
  영어로 그려진다 — 출구는 설정의 고르기다.
- **인스턴스는 하나이고 언어를 바꾼다.** 웹은 서버 렌더가 동시 요청을 한 프로세스에서 그리므로 언어마다
  바뀌지 않는 인스턴스를 둔다. 앱에는 서버 렌더가 없고 프로세스마다 한 사람이므로 흔한 모양이 맞다.
  `useTranslation()`이 언어 변경을 구독하므로 화면이 **제자리에서** 다시 그려진다 — 다시 마운트도, 잃는
  탐색 상태도 없다. 사전이 메모리에 있어 `changeLanguage`가 돌아오기 전에 적용이 끝난다(`messages.test.ts`가
  못 박는다) — 그래서 뿌리가 `useState` 초기화에서 적용하면 한국어 사용자가 영어 한 프레임을 보지 않는다.
- **언어 이름은 그 언어로 쓴다**(`English` · `한국어`, `LOCALE_ENDONYM`). 읽지 못하는 언어에 떨어진 사람이
  자기 언어를 찾는 길이 그 철자다. 그래서 사전에 넣지 않는다. 웹은 `Intl.DisplayNames`에게 묻는데 Hermes에
  그것이 없다.
- **게스트에게는 머리말 단추가 있다**(`features/settings/language-shortcut.tsx`). 설정 화면은 로그인한
  사람만 들어오므로, 없으면 게스트는 앱 안에서 언어를 바꿀 수 없다. 밝기 단추와 같은 조건(회원이 아닐 때만)과
  같은 그릇(`ChoiceSheet` — 세 값, 고르면 닫힘)이다. 회원은 `일반`의 줄을 쓴다 — 둘 다 그리면 한 값을 고치는
  자리가 둘이 된다.
- **도메인 결정은 번역하지 않는다.** `@rowcat/domain`·`@rowcat/chat`은 무엇이 적용되는지·무엇을 그릴지를
  정하고, 앱의 사전은 그 **코드에 이름을 붙인다**. 공용 패키지에 문장을 넣으면 규칙이 로케일에 묶인다.
  그 자리가 `lib/i18n/vocab.ts`다 — 웹의 같은 이름과 함수 하나하나가 짝이고(`localizedAppliedFilters`·
  `sortTriggerLabel`·`visibilityBadgeLabel`·`startLabel`·`creatorName`·`repliesLabel`…), 판정은 도메인
  함수를 부르고 낱말만 사전에서 읽는다. 도메인의 영어 표(`ORIENTATION_LABEL`·`STORY_SORT_LABEL`…)를 화면이
  직접 그리지 않는다 — 그러면 고른 언어와 무관하게 영어가 그려진다. 영어 사전이 그 표와 **한 글자도 다르지
  않다**는 것을 `vocab.test.ts`가 값으로 견준다. 계약의 신고 어휘(`REPORT_REASON_LABEL`·`REPORT_TARGET_LABEL`·
  `CAPABILITY_LABEL`·`MY_REPORT_STATE_LABEL`)도 같은 규칙이다 — `moderation` 사전이 코드로 이름을 붙이고, 점이
  든 능력 코드(`comment.write`)는 중첩 키가 된다.
- **복수형에 i18next의 복수 규칙을 쓰지 않는다.** 그 규칙은 `Intl.PluralRules`가 필요한데 Hermes가 그것을
  싣는지 확인하지 않았다. 단수가 다른 문장은 키를 둘로 두고(`totalOne`·`total`, `viewReply`·`viewReplies`)
  수는 `count`가 아닌 이름(`total`)으로 넘긴다 — `count`라는 이름이 i18next의 복수 처리를 깨운다.
- **번역하지 않는 것**: 작품·대화·프롬프트·사용자가 쓴 글(데이터다 — 그 언어는 쓴 사람의 것이다), 브랜드
  이름(`Google`·`Apple`), 오류 식별자와 코드, 로그.

- **실패 문장을 대화상자 안에서 그 자리에 굳히는 것은 허용한다.** 신고·이의 제기·페르소나 저장의 실패는 그
  순간의 문장으로 담긴다(`report-turn.ts`의 `message`). 언어를 바꾸는 자리(설정 › 일반)와 그 창은 함께 열려 있을
  수 없으므로 그 문장이 다른 언어로 남는 경우가 없다. 화면에 오래 남는 실패는 여전히 깃발로 담는다.

## 화면을 옮기는 법

1. **영어 원본에 키를 더한다** — `messages/en/<이름 공간>.ts`. 이름 공간 하나가 기능 영역 하나다(`shell`,
   `signIn`, `settings`). 새 이름 공간은 `en/index.ts`와 `ko/index.ts`에 함께 더한다.
2. **한국어를 같은 모양으로 쓴다** — `messages/ko/<이름 공간>.ts`는 `Messages["<이름 공간>"]`으로 타입이
   매여 있어, 빠진 키는 컴파일 오류다. 같은 기능이 웹에 있으면 **웹의 한국어와 같은 낱말**을 쓴다
   (`apps/web/src/lib/i18n/messages/ko/`) — 같은 자리를 두 앱이 다른 말로 부르면 다른 기능으로 읽힌다.
3. **컴포넌트는 `useTranslation`을 부른다.** `const { t } = useTranslation("settings")` 뒤 `t("…")`. 그
   훅이 언어 변경 구독이기도 하다 — 부르지 않은 컴포넌트는 언어를 바꿔도 다시 그려지지 않는다.
4. **컴포넌트가 아닌 코드는 `translator(ns)`를 그 자리에서 부른다**(실패 표·순수 문구 함수). 모듈 꼭대기에서
   부르지 않는다 — 그 순간의 언어에 굳는다.
5. **여러 곳이 색인하는 표는 `deferredGroup(ns, group)`으로 둔다**(`AUTH_FAILURE_MESSAGE`,
   `SIDEBAR_SECTION_LABEL`). 읽을 때마다 지금 언어를 읽는 게터 표라 `Record<Union, string>` 모양과 호출부가
   그대로다. 그 표를 그리는 컴포넌트도 `useTranslation`을 부른다(구독 때문이다).
6. **문장을 상태에 넣지 않는다.** 실패 문장을 `useState`에 담으면 그 문장은 담긴 순간의 언어에 남는다 —
   깃발을 담고 그릴 때 문장을 읽는다(`local-data-section.tsx`).
7. **보간은 `{{이름}}`이고 두 언어가 같은 변수를 쓴다.** 배포의 나이는 어디서나 `{{guardianAge}}`·
   `{{adultAge}}`로 쓸 수 있다(인스턴스의 기본 변수).
8. **정적 스캔이 문자열을 값으로 잡고 있으면** 그 검사를 사전 파일이나 키로 옮긴다 — 지우지 않는다. 그
   검사가 지키던 사실(웹과 같은 세 낱말, 게스트 갈래가 그대로)은 그대로 지켜야 한다.

## 검사

```bash
pnpm --filter @rowcat/mobile exec vitest run src/lib/i18n
```

- 한국어가 영어와 **같은 키**를 갖는다 · 번역이 원본과 **같은 보간 변수**를 쓴다 · 영어 원본에 한글이 없다 ·
  빈 문장이 없다(`messages.test.ts`).
- 언어 판정(`locale.test.ts`) · 선호의 관대한 읽기와 신원 없는 키(`preference.test.ts`).
- 테스트는 뿌리를 마운트하지 않으므로 영어로 돈다 — 기존 문구 검사가 그대로 영어 값을 본다.

## 기기 확인

자동 검사가 닿지 않는 것이 셋이고, 시뮬레이터·실기기에서 확인한다. **아직 하지 않았다.**

1. OS 언어를 한국어로 바꾸고(설정 › 일반 › 언어) 앱을 연다 — 첫 프레임부터 한국어인가
   (`device-locale.ts`가 Hermes에서 기대한 값을 주는가). iOS·Android 둘 다.
2. 앱이 떠 있는 동안 OS 언어를 바꾸고 돌아온다 — `system`이면 따라오는가. (iOS는 언어를 바꾸면 앱을
   끝내므로 첫째 항목과 같다. Android가 이 경로다.)
3. 설정에서 고른 뒤 긴 한국어 문장(이 기기의 데이터 확인 창, 2단계 인증 안내)이 320pt 폭에서 잘리지 않는가,
   스크린리더가 단추 이름을 새 언어로 읽는가.

## 남은 것

화면 단위로 옮긴다 — 한 번에 하나의 기능 폴더, 그 폴더의 문구 모듈과 정적 스캔을 함께. 남은 폴더:
대화(`chat`, `chat-library` — 대화 설정의 페르소나 칸은 옮겼다)·만들기(`create`)·작품 테스트
(`playtest`)·런타임 재생(`runtime-player`)·계정(`account`)·설정의 나머지(AI·페르소나·테마·푸시)·알림·
진입 게이트(`onboarding`)·성인 확인·동기화·`lib`의 실패 표들. **날짜와 수의 형식**
(`lib/format.ts`)은 아직 한 형식이다 — 그 파일을 옮길 때 로캘을 인자로 받게 한다(시간대는 제품 시간대
그대로다).
