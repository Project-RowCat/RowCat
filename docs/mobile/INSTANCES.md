# 모바일 — 여러 인스턴스에 붙는 한 앱

> 결정 기록. 지금 앱은 빌드 때 정한 API 오리진 **하나**에만 붙는다. 이 문서는 한 앱이 서로 모르는 여러
> RowCat 배포에 안전하게 붙는 모양과, 그때 **앱 코드를 바꿀 권한(OTA)이 고른 서버로 넘어가지 않는 것**을 정한다.
> DEV-16(인스턴스 선택 · 상태 격리)과 DEV-17(업데이트 서명과 인스턴스 선택의 분리)을 함께 다룬다 — 뒤의 것이
> 앞의 것의 전제다. 아직 코드는 없다. §결정(2026-11-02)을 따라 §순서대로 낸다.

## 지금의 모양

```text
EXPO_PUBLIC_API_ORIGIN     번들에 박힌다(lib/env.ts) — 없으면 시작에서 던진다
API_BASE_URL · AUTH_BASE_URL   그 하나에서 만든다
OTA updates.url            빌드 때 같은 오리진에서 만들어 네이티브 설정에 박힌다(app.config.ts)
로컬 DB                    rowcat_vnext_<sha256(memberId)>.db   (local-data/database.ts)
동기화 DEK                 SecureStore rowcat.sync.dek.<sha256(memberId)>
세션                       SecureStore rowcat.auth_*            (하나뿐)
초안 표지 파일             draft-covers-<sha256(memberId)>
인증 이미지                쿠키를 ${API_ORIGIN}/ 아래 주소에만 붙인다(lib/auth-image.ts)
푸시                       설치 하나에 Expo 토큰 하나, 세션에 묶인 등록 하나
```

모든 로컬 이름이 **회원 id 하나**에서 나온다. 인스턴스가 하나뿐일 때는 맞다 — 회원 id는 그 서버가 정하고 그
서버가 하나다. 인스턴스가 둘이 되면 이것이 첫 구멍이다.

## 신뢰 경계

```text
업데이트 권한   바이너리를 낸 쪽 — 채널 인증서와 업데이트 주소가 바이너리에 박힌다
인스턴스        회원이 고른 서버 — 데이터와 화면의 내용을 정한다. 앱 코드는 정하지 못한다
기기           로컬 DB · 키 · 개인 API 키 — 인스턴스마다 따로, 어느 인스턴스도 다른 인스턴스의 것에 닿지 않는다
```

### 업데이트 권한은 인스턴스를 따라가지 않는다 (DEV-17)

정본은 `docs/ota/ARCHITECTURE.md` §업데이트 권한과 인스턴스다. 요약하면: 업데이트 주소 · 채널 헤더 · 인증서는
빌드 환경에서만 나오는 네이티브 설정이고, JS가 그것을 바꾸는 두 함수(`setUpdateURLAndRequestHeadersOverride` ·
`setUpdateRequestHeadersOverride`)와 네이티브 모듈 이름을 정적 검사가 막으며, `ROWCAT_OTA=off`는 채널과 인증서를
이긴다. **본 인스턴스와 업데이트 권한은 같은 배포다** — 다른 인스턴스의 운영자가 낼 수 있는 것은 데이터뿐이다.

### 악의적인 인스턴스가 할 수 있는 것과 없는 것

| 할 수 있다 | 막는 것 · 남는 것 |
| --- | --- |
| 거짓 화면 내용(작품, 댓글, 알림 문구) | 그 인스턴스의 데이터일 뿐이다. 앱의 크롬은 **어느 인스턴스인지** 늘 보여 준다 |
| 다른 인스턴스와 같은 회원 id를 주장 | 로컬 이름이 (인스턴스, 회원)에서 나온다(아래) — 다른 인스턴스의 파일을 열지 못한다 |
| 런타임 작품 | 이미 QuickJS/WASM 샌드박스 안이다. 원격 이미지는 **그 인스턴스의** 프록시를 지난다 |
| 생성 요청을 부르는 작품 | 개인 API 키는 고정된 제공자 오리진으로만 간다(`lib/generation/*`의 상수). 비용은 그 회원의 키다 — 지금과 같다 |
| 공유 · 웹 링크 | 그 인스턴스가 알린 웹 오리진으로 간다. https만, 열기 전에 주소를 보인다 |
| 앱 코드 교체 | **못 한다.** 위의 업데이트 권한 |
| 다른 인스턴스의 세션 · 키 · DB | **못 한다.** 아래의 격리 |

## 인스턴스의 신원

- **신원은 정규화한 https 오리진이다**(scheme · host · port, 경로 없음). 서버가 주는 id를 신원으로 쓰지 않는다 —
  악의적인 서버는 남의 id를 주장할 수 있지만, TLS가 증명하는 오리진은 흉내 내지 못한다.
- **개발 빌드만 http와 사설 주소를 받는다**(같은 Wi-Fi의 개발 서버). 그 판단은 빌드 프로필이 한다
  (`lib/build-profile.ts`), 화면이 하지 않는다.
- **로그인 전에 검증한다**: `GET /v2/runtime-config`가 이 계약의 모양으로 답해야 한다. 지금 그 응답에는 판 번호가
  없으므로 정수 하나(`instanceProtocol`)를 더한다 — 앱이 아는 범위 밖이면 「이 앱으로는 붙을 수 없습니다」로
  멈춘다. 기능 목록이 아니다(그것은 지금처럼 `disabledFeatures` · `passwordReset` 등이 답한다).
- **본 인스턴스**: 빌드의 `EXPO_PUBLIC_API_ORIGIN`. 목록에서 지울 수 없고, 단일 인스턴스 빌드에서는 유일하다.

## 격리

```text
                       본 인스턴스(지금과 같다)                   다른 인스턴스
로컬 DB                rowcat_vnext_<h(member)>.db              rowcat_vnext_<h(origin ‖ member)>.db
동기화 DEK             rowcat.sync.dek.<h(member)>              rowcat.sync.dek.<h(origin ‖ member)>
세션                   rowcat.auth_*                            rowcat.auth.<h(origin)>_*
초안 표지 · 미디어 캐시   draft-covers-<h(member)>                 draft-covers-<h(origin ‖ member)>
개인 API 키 · 기기 설정   회원 DB 안(지금과 같다)                  그 인스턴스의 회원 DB 안
```

- **본 인스턴스의 이름은 바꾸지 않는다.** 이미 깔린 앱의 대화와 초안이 그 이름 아래 있다 — 이름을 바꾸는 것은
  문자열 하나가 아니라 데이터 이전이고(AGENTS.md §IndexedDB 이름과 같은 판단), 이전이 실패한 기기는 빈 앱을 연다.
  그래서 파생 규칙이 둘이고, 고르는 함수는 하나다(`scopeKeyFor(instance, memberId)`).
- **구분자는 길이를 앞에 붙인다** — `origin ‖ member`를 그냥 이으면 서로 다른 두 쌍이 같은 문자열이 될 수 있다
  (동기화 서명이 배운 것과 같다).
- **세션은 인스턴스마다 하나**다. Better Auth의 `storagePrefix`를 인스턴스마다 다르게 준다 — 클라이언트도
  인스턴스마다 하나 만든다(모듈 전역 하나가 아니다).
- **활성 인스턴스는 하나다.** 화면, 쿼리 캐시, 동기화 실행, SSE 깨움은 활성 인스턴스 하나만 본다. 바꾸는 것은 계정
  전환과 같은 길이다 — 쿼리 캐시를 **리셋**하고(무효화가 아니다), 지역 범위를 닫고 다른 범위를 연다.
- **인증 이미지의 쿠키**는 활성 인스턴스의 오리진 아래 주소에만 붙는다 — 지금의 `API_ORIGIN` 비교가 그 값을 읽게
  된다. 다른 인스턴스의 주소에 쿠키가 붙는 것이 이 범주에서 가장 조용한 유출이다.
- **목록은 기기 저장소에 둔다**(`rowcat_device.db`). 동기화하지 않는다 — 어느 서버에 붙는지는 그 기기의 사실이다.
  재시작과 오프라인에서는 마지막 활성 인스턴스로 연다.

## 전환 · 로그아웃 · 취소된 자격

- **로그아웃은 그 인스턴스의 세션만 지운다.** 다른 인스턴스의 세션과 모든 DEK는 남는다(지금의 「로그아웃은 접근을
  닫을 뿐 신뢰를 거두지 않는다」와 같다).
- **인스턴스 제거**는 그 인스턴스의 세션 · DB · DEK · 표지 · 푸시 등록을 지운다. 확인 대화가 「서버의 암호문은
  남는다 — 복구 코드로 다시 받을 수 있다」를 먼저 적는다(`이 기기 데이터 지우기`와 같은 문장).
- **취소된 자격**(401)은 그 인스턴스만 로그인 화면으로 보낸다. 다른 인스턴스로 넘어가지 않는다.
- **본 인스턴스는 제거할 수 없다** — 로그아웃만 된다.

## 서버 주소가 바뀔 때

- **새 주소는 새 인스턴스다.** 신원이 오리진이므로 그렇다. 회원은 새 주소에 새로 붙고, 동기화가 암호문을 복구
  코드로 다시 받는다. 옛 주소의 로컬 데이터는 회원이 그 인스턴스를 지울 때까지 그대로 남는다.
- **첫 판에는 옮기는 길이 없다**(§결정 2). 넣는다면 옛 오리진이 런타임 설정에서 `movedTo`를 알릴 때만 옮긴다 —
  새 주소가 스스로 「나는 옛 주소다」라고 말하는 것은 받지 않는다. 그것이 남의 데이터를 여는 길이다.

## 인스턴스마다 다른 로그인 수단

```text
이메일 · 비밀번호       어디서나
2단계 인증             어디서나(같은 엔드포인트)
Google · Kakao         그 인스턴스가 설정했고, 그 인스턴스의 trustedOrigins에 이 앱의 스킴이 있을 때
Apple(네이티브 시트)    본 인스턴스만 — 토큰의 aud가 이 앱의 번들 id이고, 그 번들을 등록한 것은 바이너리를 낸 쪽이다
패스키                 본 인스턴스만 — rpID와 앱의 associated domains가 맞아야 한다
```

- 다른 인스턴스에서 Apple과 패스키 버튼은 **그리지 않는다**(누르면 실패할 버튼이다). 무엇이 서는지는 그
  인스턴스의 런타임 설정과 이 표가 정한다.
- 브라우저 로그인의 마지막 구간은 일회용 코드다(§결정 4, `auth-browser.ts`) — 세션이 `rowcat://` 링크에 실리지 않으므로
  인스턴스가 늘어도 그 링크를 가로챈 앱이 얻는 것이 없다. 검증자는 그 왕복 하나에만 있고 인스턴스 사이를 건너지 않는다.

## 푸시

- **푸시는 활성 인스턴스 하나만 켠다**(첫 판). 토큰은 설치마다 하나라, 여러 인스턴스에 같은 토큰을 주면 배너가
  어느 인스턴스의 것인지 앱이 믿을 수 있는 방법이 없다 — 페이로드는 서버가 쓰고, 악의적인 인스턴스는 남의
  알림 id를 적을 수 있다. 전환은 옛 인스턴스의 등록을 지우고 새 인스턴스에 등록한다.
- Expo 프로젝트의 「강화된 푸시 보안」(접근 토큰 필수)을 켜면 다른 인스턴스는 이 앱에 푸시를 보내지 못한다 —
  바이너리를 낸 쪽의 운영 결정이고, 켜면 다른 인스턴스의 푸시는 꺼진다.

## 하위 호환

- **단일 인스턴스 빌드가 기본이다.** 목록은 본 인스턴스 하나이고, 고르는 화면이 서지 않는다. 화면 · 저장 이름 ·
  동작이 지금과 바이트 단위로 같다.
- 여러 인스턴스는 빌드 설정 하나로 연다(`EXPO_PUBLIC_INSTANCE_SELECTION=on`). 이 값은 공개되어도 무해하다.
  네이티브 세대를 올리지 않는다 — 바뀌는 것은 JS뿐이다.

## 시험

- 정적: 두 재정의 함수와 `expo-updates` 가져오기가 없다 · 업데이트 주소는
  `app.config.ts`의 빌드 환경에서만 나온다 · `ROWCAT_OTA=off`면 `updates.enabled === false`이고 주소가 없다.
- 값: `scopeKeyFor`가 본 인스턴스에서 지금의 이름을 그대로 내고, 다른 인스턴스에서 같은 회원 id라도 다른 이름을
  낸다 · 구분자 충돌이 없다 · 인증 이미지가 다른 오리진에 쿠키를 붙이지 않는다.
- 악의적인 서버: 남의 회원 id를 주장하는 `/me`, `movedTo`를 거짓으로 주장하는 새 주소, 판 번호 밖의 런타임 설정.
- 기기: iOS · 안드로이드에서 두 인스턴스 로그인 → 전환 → 재시작 → 오프라인 → 한쪽 401. 시뮬레이터가 아닌 측정이
  필요한 것은 「재지 않았다」로 적는다.

## 결정 (2026-11-02)

1. **포크가 켠다.** 기본 빌드는 단일 인스턴스이고 지금과 같다. 여러 인스턴스는 `EXPO_PUBLIC_INSTANCE_SELECTION=on`
   으로 연다 — 이 저장소는 스토어 앱을 내지 않으므로, 켜는 쪽은 바이너리를 낸 포크다.
2. **새 주소는 새 인스턴스다.** `movedTo`로 옮기는 길은 첫 판에 없다(§서버 주소가 바뀔 때).
3. **푸시는 활성 인스턴스 하나만.** 전환이 등록을 옮긴다(§푸시).
4. **세션 전달을 먼저 고친다.** `rowcat://`로 세션을 넘기는 브라우저 로그인을 검증된 https 링크(Universal Link ·
   App Link)나 일회용 교환 코드로 바꾸는 일이 이 슬라이스보다 앞의 독립된 일이다. 인스턴스가 늘면 그 약점이 함께
   늘어나기 때문이다. **일회용 코드로 닫았다**(DEV-61) — 네이티브 재빌드와 도메인 연결 파일이 필요 없었다.
