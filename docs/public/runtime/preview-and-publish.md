# 미리보기와 발행

## 미리보기

스튜디오의 **미리보기 실행**은 지금 편집기에 있는 파일들로 런타임을 실제로 돌립니다. 아무것도
서버에 올라가지 않고, 작품의 저장 데이터도 건드리지 않습니다 — 미리보기의 진행은 스튜디오가
열려 있는 동안만 살고 새로고침하면 사라집니다.

### 검사가 먼저입니다

`Problems`에 막는 오류가 남아 있으면 실행 버튼이 켜지지 않습니다. 경고는 실행을 막지 않습니다.

### 저절로 다시 돌지 않습니다

코드를 고치면 미리보기에 `변경사항 있음`이 뜹니다. 도는 화면은 그대로이고 **다시 시작**이 새
코드를 돌립니다. 새 코드로 갈아 끼우면서 화면의 상태를 옮겨 주는 기능(핫 리로드)은 없습니다 —
`useState`의 값은 다시 시작할 때마다 처음부터입니다.

### 초기화가 셋입니다

```text
다시 시작        새 코드로 다시 돌린다. 저장 상태·영구 상태는 **이어받는다**
플레이 초기화     플레이스루 상태(useStoryState)만 비운다. 영구 상태는 남는다
긴 진행 초기화    영구 상태(usePersistentState)까지 비운다 — 스튜디오에만 있는 조작이다
```

세 조작이 다른 이유는 [상태](/docs/runtime/concepts/state)의 세 수명이 다르기 때문입니다.
발행된 작품의 플레이어에게는 앞의 둘만 있습니다.

### AI는 꺼진 채로 시작합니다

미리보기의 `AI 사용`은 기본이 꺼짐입니다. 켜면 `useGeneration()`이 **당신의 계정 설정으로**
실제 요청을 보냅니다 — 관리형이면 이 서버 운영자의 키가 쓰이고, 직접 연결한 제공자면 그 키가 쓰입니다. 토글은
다음 실행·다시 시작부터 적용됩니다.

### 콘솔

`console.log`·`console.warn`·`console.error`는 바닥 패널의 `Console`에 모입니다. 런타임이
낸 진단(중복 `key`, 사라진 컴포넌트의 상태 갱신 등)도 같은 자리에 옵니다. `State` 칸은 지금
저장된 플레이스루 상태와 영구 상태를 그대로 보여 줍니다.

## 발행

런타임이 켜진 초안을 발행하면 RowCat 서버가 소스를 **다시 컴파일**해서 발행본에 붙입니다.
컴파일에 실패하면 발행이 거절되고 이미 발행된 판은 한 글자도 바뀌지 않습니다.

발행된 작품의 상세 화면에는 `대화 시작` 대신 **플레이**가 섭니다. 플레이어가 그 버튼을 누르면
당신의 런타임이 RowCat의 대화 화면 자리에서 열립니다.

### 플레이어의 진행은 저장됩니다

`useStoryState`·`usePersistentState`의 값은 플레이어의 계정에 저장되어 그 사람의 다른 기기로
건너갑니다. 플레이어에게는 **다시 시작**과 **플레이 초기화**가 있고, 영구 상태를 지우는 조작은
없습니다.

### 재발행은 도는 세션을 바꾸지 않습니다

코드를 고쳐 다시 발행해도 이미 열려 있는 플레이는 그대로입니다. 새로 여는 플레이가 새 코드를
받습니다. 저장된 진행은 코드와 무관하게 남으므로, 저장 모양을 바꿨다면
[마이그레이션](/docs/runtime/concepts/state#마이그레이션)을 적어야 합니다.

### 발행된 코드는 비밀이 아닙니다

컴파일된 런타임은 플레이어의 **기기에서** 실행됩니다. 문자열·인물 지시문·분기 규칙은 열어 볼
수 있다고 보아야 합니다. API 키, 비밀번호, 개인 토큰을 소스에 적지 마세요 — 자세한 것은
[보안과 샌드박스](/docs/runtime/runtime-model/security#비밀을-적지-마세요)에 있습니다.

### 런타임을 끄면

편집기에서 런타임을 끄고 다시 발행하면 발행본에서 런타임이 빠지고 작품은 대화 작품으로
돌아갑니다. 스튜디오의 파일은 지워지지 않습니다 — 지우는 것은 별개의 조작이고 확인을
요구합니다.
