# AI 코딩 도구로 만들기

런타임 프로젝트는 평범한 TypeScript 프로젝트입니다. 그래서 코딩 에이전트가 그것을 읽고
고칠 수 있고, RowCat은 그 도구가 **RowCat 안에서** 일하도록 다리 하나를 제공합니다.

```text
"호감도가 5 이상이면 상대가 먼저 고백하도록 바꿔줘"
        ↓
에이전트가 프로젝트를 읽고 · 문서를 찾고 · 코드를 고치고
        ↓
컴파일하고 · 미리보기를 돌리고 · 버튼을 눌러 확인하고
        ↓
당신의 초안에 저장된다 — 스튜디오를 열면 그 코드가 있습니다
```

저장되는 것은 **평범한 런타임 소스**입니다. 에이전트가 만든 프로젝트도 스튜디오에서 그대로
열리고, 손으로 고친 프로젝트를 에이전트가 이어받을 수도 있습니다. 별도의 형식도, 별도의
저장소도 없습니다.

## 무엇이 필요한가

- Node 22 이상이 설치된 컴퓨터
- MCP를 지원하는 코딩 도구(Claude Code · Codex · Cursor 등)
- RowCat 계정과, **이미 동기화를 켜 둔 RowCat 기기 하나**(웹이나 앱)

세 번째가 왜 필요한지가 이 도구의 성격입니다. RowCat의 초안은 **당신의 기기에 있고 서버에는
열 수 없는 암호문만** 있습니다. 그래서 이 도구는 당신의 컴퓨터에서 돌면서 스스로 하나의
기기가 되고, 기기를 늘리는 방법은 이미 쓰고 있는 기기에서 **승인해 주는 것**입니다.

## 설치와 연결

이름이 둘입니다. **설치하는 것과 실행하는 것이 다릅니다** — 아래 모든 예시가 이 구분을
따릅니다.

```text
npm 패키지 이름   @rowcat/mcp    npm·pnpm에 넘기는 값
설치 뒤의 명령    rowcat-mcp     터미널과 MCP 설정에 적는 값
```

```bash
npm install -g @rowcat/mcp@next
```

`@next`는 프리릴리스 채널입니다 — 나가 있는 것은 아직 카나리아뿐이고 `latest`(안정판)는
없습니다. `pnpm add -g @rowcat/mcp@next`도, 설치 없이 한 번만 써 보는
`npx @rowcat/mcp@next setup`도 같은 자리에 섭니다.

설치가 끝나면 명령은 `rowcat-mcp`입니다.

```bash
rowcat-mcp setup
```

이 한 줄이 전부입니다. 로그인을 묻고, 페어링 코드를 보여 주고, 승인이 오면 연결까지 끝냅니다.

```text
RowCat MCP 설정

✓ 세나로 로그인했습니다.

페어링 코드:
  J7FK-W2MR-9QXP-4B1D

이미 연결된 RowCat 기기에서 열어 주세요:
  계정 → 데이터 → 새 기기 연결

위 코드를 입력하고 이 기기를 승인합니다.

승인을 기다리는 중…

✓ 기기가 승인되었습니다
✓ 동기화 키를 받아 확인했습니다
✓ RowCat MCP를 쓸 준비가 됐습니다.
```

코드는 5분 동안만 살아 있고, 승인하는 화면은 웹과 앱이 같습니다 —
**계정 → 데이터 → 새 기기 연결**. 새 기기를 연결할 때 늘 쓰는 그 화면입니다.

그다음 쓰는 도구의 MCP 설정에 서버를 추가합니다. 설정 파일에는 **띄울 명령만** 적고,
아이디도 비밀번호도 페어링 코드도 적지 않습니다 — 필요한 값은 `setup`이 이미 당신의 홈
디렉터리에 0600 권한으로 두었습니다.

```json
{
	"mcpServers": {
		"rowcat-runtime": {
			"command": "rowcat-mcp",
			"args": ["serve"]
		}
	}
}
```

여기 서는 것은 **명령 이름**입니다. 패키지 이름(`@rowcat/mcp`)은 설치할 때 한 번 쓰고,
그 뒤로는 나오지 않습니다. 두 번째부터는 `rowcat-mcp serve`뿐이고, 연결은 한 번으로
끝납니다.

### 승인할 기기가 없다면

컴퓨터가 이 한 대뿐이거나 다른 기기에서 동기화가 잠겨 있다면, 복구 코드로 여는 길이 그대로
있습니다.

```text
rowcat-mcp unlock
```

이 길은 사라지지 않았습니다. 다만 종이를 찾아와야 하는 절차라 **기본 경로가 아닙니다** —
승인할 기기가 하나라도 있다면 `setup` 쪽이 훨씬 짧습니다. 어느 길로 열었든 그 뒤의 동작은
똑같습니다.

### 계정을 바꾸면

계정을 바꿔 로그인하면 **앞 계정의 동기화 키는 지워집니다.** 봉투 키는 그것을 연 계정의
것이고 다른 계정의 초안을 열지 못합니다 — 새 계정으로 `rowcat-mcp setup`을 한 번 더
실행해 주세요.

## 에이전트가 할 수 있는 것

```text
프로젝트 목록 · 파일 읽기 · 파일 쓰기·만들기·이름 바꾸기·지우기
컴파일과 진단
런타임 문서 검색 · API 레퍼런스 조회
미리보기 시작·다시 시작·정지
그려진 화면 트리 읽기 · 버튼 누르기 · 글 넣기 · 제출하기
콘솔과 저장 상태 보기
```

마지막 두 줄이 이 다리의 핵심입니다. 에이전트는 코드를 고치는 데서 멈추지 않고 **실제로
실행해서 눌러 봅니다** — 컴파일이 통과했다는 것은 화면이 옳다는 뜻이 아니고, 그 차이를
확인하지 않으면 "되는 것처럼 보이는 코드"가 그대로 남습니다.

## 할 수 없는 것

```text
발행                작품을 공개하는 일은 사람이 누릅니다
런타임 켜기·끄기     제작자의 결정입니다
프롬프트·로어·시작 장면 편집   런타임이 켜진 초안에서 그 넷은 잠깁니다
대화·개인정보        이 도구는 그 어느 것도 읽지 못합니다
```

에이전트가 손댈 수 있는 것은 **런타임이 켜진 초안의 코드 파일**뿐입니다. 그 밖의 것을
부탁하면 도구가 없다고 답합니다.

## 안전에 대해 알아 둘 것

- **동기화 키가 그 컴퓨터의 파일에 저장됩니다.** 그 파일을 읽을 수 있는 사람은 당신의 초안을
  열 수 있습니다. 여럿이 쓰는 컴퓨터에서는 쓰지 마세요.
- **에이전트가 고친 것은 곧바로 당신의 다른 기기로 갑니다.** 실수도 함께 갑니다 — 큰 변경을
  맡기기 전에 스튜디오에서 지금 상태를 확인해 두는 편이 좋습니다.
- **같은 파일을 두 곳에서 고치면 에이전트 쪽이 멈춥니다.** 에이전트가 파일을 읽은 뒤에
  스튜디오나 다른 기기가 그 파일을 고쳤다면, 에이전트의 쓰기는 조용히 덮어쓰지 않고
  실패합니다. 그때 에이전트는 새 내용을 다시 읽고 합칩니다.
- **미리보기는 격리된 VM에서 돕니다.** 스튜디오의 미리보기와 같은 실행 환경이고, 코드는
  여전히 당신의 브라우저나 이 도구의 프로세스가 아니라 그 VM 안에서만 실행됩니다.

## 이 도구의 라이선스

`@rowcat/mcp`는 **GNU Affero General Public License v3.0**(`AGPL-3.0-only`)으로 배포되는 자유
소프트웨어입니다. 조건은 설치된 패키지에 함께 들어 있는 `LICENSE` 파일이 전부이고, 아래는 그
요약입니다 — 요약이 원문을 대신하지 않습니다.

```text
할 수 있는 것   어떤 목적으로든 실행하고 · 들여다보고 · 고치고 · 다시 배포한다
다시 배포할 때  같은 라이선스로, 대응하는 소스와 함께 낸다
고친 판을       네트워크 너머의 사용자가 쓰게 하면 그 사용자에게도 소스를 내놓는다
보증            없다
```

**당신이 쓴 코드는 당신의 것입니다.** 이 라이선스가 다루는 것은 도구 자체이고, 이 도구로
쓰고 고친 런타임 소스·프로젝트 파일·에셋의 소유권을 주장하지 않습니다. 함께 설치되는
서드파티 패키지도 각자의 라이선스를 그대로 따릅니다.

## 잘 부탁하는 법

에이전트에게 맡길 때 가장 잘 통하는 것은 **작고 확인 가능한 요청**입니다.

```text
좋음   "메신저 화면에서 상대가 답장하기 전에 '입력 중' 표시를 3초쯤 보여 줘"
좋음   "이 오류 고치고 미리보기로 버튼까지 눌러서 확인해 줘"
어려움  "이 작품을 처음부터 다시 만들어 줘"
```

마지막 요청이 어려운 이유는 능력이 아니라 되돌리기입니다. 프로젝트를 통째로 다시 쓰면
당신이 쓴 코드에 담긴 의도가 사라지고, 그것을 되돌릴 방법은 없습니다.
